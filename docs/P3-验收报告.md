## 二、计划外内容（执行中发现 / 用户新增 / 取代规划）

### 2.1 P3 实机验收发现的问题（P3.1 节）
1. **歌词行显示为类型名**（严重）：ItemsControl 的 ItemTemplate 未生效走了 ToString()。八次提交（315c63b~c19e021）未修复 → **推倒重做**，由 UI-R0 自绘路线取代。**结论存档：基于 ItemsControl/DataTemplate/ScrollViewer 的歌词渲染路径在本项目判死刑，禁止再修，重做必须走自绘（OnRender + FormattedText）**。
2. **歌词页交互不可用**（严重）：按钮与窗口按钮重叠、点击无反应、无法退出 → 由 UI-R0/R1 解决（自绘控件 + 右键菜单 + Esc + 点击封面收起）。

### 2.2 用户新增需求（P3.1 ③④，已落地）
3. **内嵌标签歌词**：TagLibSharp 读内嵌歌词（USLT/LYRICS），带时间轴按 LRC 滚动、纯文本静态展示；优先级插入第二级；**有内嵌歌词的曲目不发任何 API 调用**（harness 断言）。✅
4. **额度指示迁移**：播放条「API 剩 N」移除，只在设置页在线组展示（免费/兑换余量）。✅

### 2.4 执行中记录的技术决策与坑
- 网易云匹配加**时长差 < 3s 硬条件**（打样实测 UGC/翻唱为主，只靠标题+歌手会大量误配，见 docs/api-samples/README）。
- **netease_id 列迁移顺序坑**：旧库上 CREATE INDEX 必须等列加好之后单独建，否则整批 DDL 失败导致启动退出——已在 Db.EnsureSchema 修正。
- 歌词缓存走 lyrics_cache 表（163:{id} → lrc/tlyric/romalrc；偏移 offset:{path-hash}）；在线歌词成功后落盘同目录 .lrc（秒读，已有不覆盖）。
- 扫描 Upsert 不触碰 netease_id 列（重扫不冲掉用户匹配）。
- 手动重新匹配做成独立对话框（RematchDialog）而非页面内嵌。
- 离线构建辅助：本机 nuget.org TLS 失败，用 tools/nuget-offline/ 作为 fallbackPackageFolders（不入仓）；构建需 -p:RestoreIgnoreFailedSources=true -p:UseSharedCompilation=false -m:1 -nodeReuse:false。

### 2.5 最近一轮歌词遗留问题修复（2026-08-14）
- **窄歌词栏省略号截断**：改为减少显示句数——当前播放行完整文本不省略（超宽时自适应缩小字号），其余行整句放不下则不显示；fit 判断用无约束自然宽度（约束后 Width 会被截断导致判断失真）。✅

## 四、交付物与技术档案（供 fable5 上下文）

### 测试基线（harness，全部离线可跑）
- dotnet run --project tools/Player.Harness -- seamless → 26 项
- -- lyrics → 101 项（LRC 解析/令牌桶/额度头/匹配/脱敏/错误映射/缓存/内嵌歌词/离线降级/头部元数据）
- -- grouping → 13 项
- -- theme → 17 项（取色 + 深浅两套对比度保底）
- -- library <目录> → 曲库链路
- 运行全部：约 157+ 项全过（library 需真实目录）

### 关键架构铁律
- **XAML 铁律**：列表/歌词相关模板一律在元素上内联定义，禁止资源字典隐式模板；歌词控件与分组列表不使用 WPF-UI 控件样式。
- **歌词自绘**：LyricCanvas（FrameworkElement + OnRender + FormattedText），禁止 ItemsControl/ListBox/DataTemplate/ScrollViewer 组合。
- **主题机制**：13 个主题刷子全量 DynamicResource；ThemeService 四模式（底色×染色）+ 300ms 过渡 + WPF-UI ApplicationThemeManager 联动 + AccentFill 资源覆盖。
- **纯函数进 Core**：分组（TrackGrouper）、取色派生（ThemeEngine）、歌词布局（LyricLayout）、LRC（LrcParser）等全部 Player.Core 纯函数 + harness 断言。

### 构建/发布
- 构建：dotnet build Player.App/Player.App.csproj -c Debug --no-restore -p:UseSharedCompilation=false -m:1 -nodeReuse:false
- 发布：dotnet publish Player.App/Player.App.csproj -c Release -r win-x64 --self-contained true -o publish（发布前先停 Player 进程）
- 工作流：每步 = 提交 + 发布 + 用户目验后才进下一步（已连续执行 R0–R4）
