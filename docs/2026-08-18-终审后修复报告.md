## 修复内容

### 播放与歌词

- 播放引擎为 Open 请求增加代际校验和在途原生操作退出屏障；旧慢请求不能覆盖较新的播放请求，BASS 全局关闭前会排空所有建流/释放调用。
- 打开损坏或不支持的文件失败时保留当前播放，不再先释放已有音频链路。
- 播放列表增加事务快照；候选曲全部打开失败时恢复原队列、模式、随机顺序和当前曲，避免 UI 与实际音频分叉。
- 随机播放完成一轮后不会立即重复当前曲。
- 切歌时立即清空旧歌词；在线歌词改为同目录临时文件加原子无覆盖落盘，退出时限时等待本地写入，网络盘异常不会无限拖住进程，绝不覆盖用户同时创建的 `.lrc`。

### 媒体库

- 根目录删除与扫描共用串行锁，扫描只在取得锁后捕获 roots，避免旧扫描在删除后重新写回曲目。
- 根目录删除等待扫描收敛时不再使用生命周期取消；即使退出流程已启动，也不会留下配置已移除但数据库仍残留的曲目。
- 删除父根目录时保留仍配置的嵌套根目录、曲目和歌单关系。
- 子目录无权限时将该根扫描标记为不完整，不根据不完整结果删除现有曲目。
- 文件修改时间改用 UTC ticks，修复同一毫秒内变化被漏判的问题。
- 删除或重命名带点目录时仍会进入监听补扫。

### 在线、下载与配置

- ChKSz 响应同时校验 HTTP 状态和响应体的 `code`、`msg`、`data`；所有上游错误统一脱敏。
- 保留 `401/402/429` 状态语义，下载层只重试没有 HTTP 状态的瞬时网络失败。
- 带 Key 的 ChKSz 端点强制 HTTPS；歌单请求的 60 秒超时现在真正生效。
- 旧 `ApiKey` 迁移只填充缺少 Key 的 ChKSz 端点，不覆盖用户已有端点，并在迁移后清空旧字段。
- 下载目标经过规范化并限制在下载根目录；同名文件通过原子占位生成 `(2)`、`(3)`，不再覆盖已有文件。
- 下载后的 `.lrc` 使用同一套原子无覆盖落盘，歌词失败作为 best-effort 附件，不会把已经落盘的音频误标为失败。
- GD HTTP 非 2xx 状态完整传播到统一结果，429/503 不会再被下载层误判为无状态网络失败并重复整链请求。

### 应用与窗口

- 启动异常进入致命退出，避免无主窗残留进程；启动扫描后台化，不再阻塞首屏。
- 外部文件冷启动和热启动统一为临时播放/入队语义。
- 退出清理各步骤独立容错；单实例命名管道限制为当前用户并增加 5 秒读取超时。
- 桌面歌词按显示器工作区定位，拖动和缩放在捕获丢失时正确结束，避免窗口卡在拖动状态。
- API Key 输入改为默认掩码、显示尾四位，并提供按住显示按钮；长度不超过四位的短 Key 也不会泄露原文。

## 保留的低优先级残余

`DirectSoundBackend` 在同一进程内依次切换多个 BASS 输出设备时，已初始化但不再使用的设备可能保留到全局 `BassRuntime.Shutdown()` 才释放。立即逐设备调用 `Bass.Free()` 会与当前 mixer、DSP 和输出后端的销毁顺序耦合；本轮没有在缺少多设备实机矩阵的情况下贸然改动。正常使用一个默认输出设备、切换 WASAPI/ASIO、退出应用均不受影响。后续如要处理，应先增加多 DirectSound 设备切换的实机资源计数测试。
